# V1 kernel and controller contract

Status: selected design, 2026-10-13; **not implemented or qualified**. This specifies the mechanisms for findings 1–6 and 8 of the [independent attack](../reviews/2026-10-13-architecture-attack.md) and is the normative kernel/controller companion to the revised main architecture. Target API, firmware and physical validation remain required.

## Scope and authority

V1 supports one restrained wheel-pair fixture requiring neither active balance nor powered load holding. Its protective response requests zero drive and output disable; electrical disable and resulting coast must be qualified. No braking-distance, humanoid stabilization or active-hold claim follows. A trusted local skill converts bounded task targets to typed wheel commands; it has no raw transport. Its lifetime is separate from the remote agent's, but its command authority remains bounded by its operation/grant. It may continue an already admitted skill only to that operation's fixed deadline. Controller-side expiry remains independent of Linux and never depends on model or recorder progress.

The mandatory custom kernel component owns one copied typed command, fixed limits, effective grant, generation, operation lifecycle and exclusive endpoint dispatch. Its V1 command is `WheelDutyPair`: signed integer left/right drive duty in permille, representable range [-1000, 1000], with no unit/mode switching. Installed target ceilings may be much smaller; representability is not physical permission. Wiring polarity, channel order, numeric/slew ceilings and zero/disable behavior are immutable qualified profile data. Userspace owns artifact execution, inference, durable intent and recording. Dedicated serdev UART and C remain engineering candidates conditional on the main architecture's exact-target comparison/build gates. USB/CAN/vendor paths require another named backend.

## One serialization order, urgent closure

One per-endpoint authority mutex serializes effective state changes and every `serdev_device_write_buf()` call. A bounded worker processes ordinary admission/RX/transmit events. **Urgent close ioctls acquire the same mutex directly**, rather than waiting behind its FIFO. Thus the worker is not the exclusive mutator; the mutex defines the sole mutation order. No second userspace ownership table is authoritative.

The worker checks pending closure, expiry, owner liveness and evidence health before ordinary work, handles at most one bounded event/frame-prefix write per lock acquisition, then releases the mutex. Validated closure publishes expected lifetime/generation/transition identities into fixed control slots for endpoint fault/detach, grant revoke and operation cancel before waiting for the mutex. Under a bounded IRQ-safe control lock, requests merge monotonically: detach/fault dominates grant revoke, which dominates operation cancel. A weaker request cannot erase a stronger one; a stale request cannot overwrite a current identity. Overflow of a required closure slot escalates to endpoint fault rather than dropping closure. Timers/callbacks use these slots and schedule work without acquiring the authority mutex.

Pending closure is notification, not a second effective grant table. Ordinary writes stop while it is pending. Under the authority mutex, revalidate slot identities and commit effective closure; clear only the exact slot revision processed, leaving concurrently published requests pending. Never hold the control lock while acquiring the authority mutex or calling the UART; callbacks never acquire the authority mutex. Interrupted callers do not withdraw an accepted closure. RX queues cannot consume control-slot storage. This prevents cancel/revoke/teardown races from downgrading closure without inventing a scheduling guarantee.

| Event / receipt | Meaning and ordering |
|---|---|
| `CLOSE_REQUESTED` | RPC/event accepted; authority might still be effective. An interrupted syscall returns no stronger claim. Query by transition ID. |
| `LOCALLY_CLOSED` | Under the mutex, mark grant/operation ineligible, advance the applicable generation, close child streams and discard unsent work. This is the linearization point. |
| `RECONCILED` | Matching controller barrier received and processed before the transition's absolute deadline; establishes only the declared controller state. |
| `FAULT_LATCHED` | Timeout, owner loss or protective fault closes eligibility; a delayed receipt cannot undo it. |

After local closure, no new experiment frame may enter the UART buffer. Only the exact started-frame recovery allowance below and protective protocol frames remain eligible. Each such write checks detached state, recovery/session identity and deadline. The mutex may be held across one asynchronous buffer-write call, never a drain, synchronous write, controller wait, allocation, filesystem or network operation. Actual UART-driver call duration and callback reentrancy must pass target inspection; “asynchronous” alone gives no scheduling bound. No callback may reacquire the authority mutex from that call. Event capture uses a separate bounded queue lock; the worker releases it before taking the authority mutex.

Expiry is checked using current robot boot-time clock at every transition, including processing receipts captured earlier. Deadline/closure wins over completion at equality. Owner-death detection is not instantaneous; local closure latency, retained UART bytes and physical response are separate measurements. If Linux cannot run the closure path, controller expiry is the remaining response.

## New fixture wire protocol

The proposed **Voln fixture wire v2 is incompatible with existing Shrike v1**. Existing codec/state-machine tests are extraction material, not implementation of this contract. There is no automatic v1 fallback or live protocol negotiation.

The dedicated physical link is trusted against hostile injection; CRC detects corruption, not authentication. Use bounded delimiter framing, fixed permitted message lengths, CRC, explicit version, and finite parser storage/timeouts. An invalid frame cannot refresh liveness. Every command, start/rearm, quiesce, fault, receipt and other state-changing message carries:

`device_identity, controller_boot, controller_session, host_runtime_nonce, grant_generation, operation_id, stream_id, sequence, transaction_id` as applicable. Unused fields have canonical zero values, not wildcard meanings. Commands additionally carry typed values and an **absolute controller-clock expiry**. Receipts echo the identities and controller state/time they actually establish.

The controller durably increments a nonwrapping boot counter before accepting handshakes; failed/ambiguous persistence inhibits output. It creates a fresh nonwrapping session counter/challenge for each handshake while inhibited. The host supplies a fresh 128-bit runtime nonce from initialized kernel randomness and accepts only the matching response. Rearm consumes that challenge once. Replayed handshakes cannot reuse an old session. Counter exhaustion inhibits and requires servicing; firmware reinstall cannot silently reset the device identity/counter namespace. Commissioning a replacement identity requires explicit operator recovery. This is a selected firmware requirement, not a verified property of a Shrike/RP2040 board.

Any controller reset starts with outputs inhibited and previous sessions invalid. The host closes authority on a changed boot/session or lost link; it cannot infer absence of a reset merely from missing telemetry. Old commands retained in UART buffers are rejected by identity after reset and by expiry without a reset. Host/module restart likewise creates a new session and cannot adopt the old operation. Within a session, grant generations never decrease and operation numbers strictly increase. `START` advances the operation high-watermark but never actuates; quiesce also retires an operation that has not started. A command cannot reopen a retired operation, and a sample cannot mint a grant or operation.

The kernel-issued operation epoch includes device identity, controller boot/session and host runtime nonce; live operation IDs cannot be allocated until that handshake completes. Durable boot plus per-boot session counters prevent reuse of the full wire epoch; the nonce is not the sole uniqueness argument. Offline software fixtures use a separate non-actuating identity namespace.

The handshake establishes a bounded mapping between host boot-time and controller monotonic ticks, including measured exchange uncertainty and specified oscillator drift. Host cutoff `H` is the minimum of grant, parent operation, required observation-validity cutoff and the sample's finite dispatch horizon; credential/health ceilings constrain grant/operation as applicable. Choose controller expiry no later than the conservative lower bound on controller ticks at `H`. Invalid/too-uncertain mapping inhibits; recalibration is performed inhibited. Controller expiry is checked before applying each command and throughout execution. Neither delayed receipt nor acknowledgement renews it. An operation has a controller-enforced absolute end time; sample deadlines cannot exceed it. No remote wall clock is authoritative.

### Selected partial-frame rule: finish one old frame, then quiesce

There is at most one started command frame, one replaceable unsent sample, and no transmission of a subsequent sample until the current sample's controller receipt. This deliberately limits V1 throughput; it is not a servo-rate promise.

On close, drop the unsent sample. If a frame has started, finish **only its exact immutable remaining bytes**, with its original identities/expiry, within the profile's recovery deadline. Do not append new command content, increase its horizon or refresh its grant. That old frame may still cause a residual effect before its original expiry. Then send a uniquely identified quiesce barrier, without waiting for the old command receipt. If completion stalls or errors, stop sending, latch a fault and rely on independent endpoint expiry; do not splice stop bytes into the partial frame.

The controller processes complete frames in order, closes the named operation/session on quiesce, removes pending task work, requests zero/disable, then acknowledges the resulting controller state. Unknown sink/disable status produces no successful reconciliation receipt. Normal quiescence does not set the protective fault latch. Timeout, reset, host loss and protective intervention do; these require explicit operator rearm. Reopening after a transport fault requires inhibited parser/transport recovery and a fresh handshake. A flush alone is insufficient.

A successful sample receipt is `SAMPLE_APPLIED`: emitted only after the controller sink/command-register update succeeds, echoing the actual applied duty pair and controller application time. Parsed/queued receipt is insufficient. Unknown application status faults instead of supplying a slew baseline. Initial rearm and matched quiesce establish an explicit disabled-zero baseline/time before the first new sample. These are controller-reported command/output-state facts; they do not measure wheel motion or prove electrical disable independently. Host/kernel evidence must retain that distinction.

| Transition | Following state |
|---|---|
| Normal operation cancel + matched quiesce | Operation terminal; grant may remain usable for a distinct operation within its existing authorization. |
| Normal grant revoke/replacement + matched quiesce | Host `READY`; new preauthorized grant may activate, with fresh instance state. No old operation reopens. |
| Expiry, owner loss, reset or uncertain handoff | Host `FAULT_LATCHED`; authorized recovery/reconciliation leads to `INHIBITED`, then explicit operator rearm. Controller starts reset inhibited and rejects task frames until recovery. |

`RECONCILED` proves controller protocol/commanded-output facts, never cessation of measured wheel motion. Encoder/electrical measurements remain separately sourced evidence.

## Operations, samples and observations

An operation binds immutable skill/configuration digest, permitted group, envelope and finite duration. The durable external request key maps to that one operation even after daemon restart. One operation occupies the group. Its stream ID is fresh and nonreusable; cancel atomically closes its stream without needing to revoke unrelated grant permissions.

Initial RPC proposal supplies an attempt-scoped stable request key and immutable parent digest, not an invented operation ID. The robot allocates and durably binds the operation ID before possible dispatch, then returns it. Key-based retries resolve that original record; child submissions, query and cancel use its returned identity. The kernel sees only robot-issued identities under its runtime epoch.

V1 exposes latest-value samples, not arbitrary queued trajectories. Each sample has `(operation_id, stream_id, sequence)` plus its own digest, acquisition context and absolute deadline. A higher sequence replaces only the unsent mailbox; it cannot replace a started frame or controller effect. The current identical duplicate returns existing status and never refreshes deadlines; changed-payload duplicate is rejected. Older sequences outside the retained bounded result slot are rejected as retired, never replayed. Sequence exhaustion terminates the stream; wrap is forbidden. V1 rejects chunk/trajectory submission. A future chunk protocol must separately identify predicted, replaceable, dispatched and applied prefixes before supporting RTC-style policies.

The kernel and controller reject samples for closed operations, retired sessions, incompatible revisions or expired windows, even if their enclosing grant once matched. Durable unfinished operations become `OUTCOME_UNKNOWN` after restart; no automatic resend/new-key substitution is permitted.

Observation IDs are scoped to source boot/session and nonreusing sequence. The copied kernel context includes earliest/latest acquisition time, validity, source, clock-map and calibration revisions. Dispatch uses the oldest possible acquisition time for maximum-age checks; future/inconsistent intervals, absent retained IDs and excessive uncertainty reject. Fresh host receipt cannot replace acquisition time. Payload identity and inference lineage remain userspace obligations; this kernel record does not prove what a model saw.

V1 calibration, clock-map and fixed-limit revisions change **only while inhibited**. Updating them under the authority mutex invalidates dependent observations and queued samples, advances context revision and requires explicit rearm. No active hot calibration exists. For V1 slew limits, track the last complete controller-accepted sample and controller application time from its receipt; while its status is unknown, do not start another sample. Clamp elapsed-time credit to a profile maximum so silence does not permit an arbitrarily large step. The controller independently enforces the same configured numeric/slew ceiling against its actual last applied output. Protective disable may bypass ordinary slew limits under its fixed protective rule; its physical response requires qualification.

## Owner, teardown and power management

Registration binds the original daemon thread-group leader's referenced task/PID identity, not a numeric PID or descriptor lifetime. Runtime calls require the same thread-group identity and authorized credentials; forked/FD-transferred callers cannot acquire that authority. Duplicates do not extend the registered owner's lifetime. Conservatively, leader exit closes authority even if another group thread survives. Before each write and on a periodic watchdog pass, check under RCU that the referenced leader is still the registered identity and is not exiting/dead. The check-to-write race remains bounded by one call plus controller expiry; no instant-death claim is made.

After its initial executable startup, the trusted `voln-robotd` startup code installs seccomp denial of `execve`/`execveat` before spawning worker threads or registering authority; new threads inherit it. If a selected runtime has already created threads, the filter must synchronize across the group or startup fails before registration. The external launcher cannot attach a filter to an already running process by assertion. Exec is not a supported way to replace the owner. Close/replacement/restart requires fresh registration. Final file release requests closure promptly but is not the only death detector. No private pidfd internals, unexported death hook or forced module unload is required.

Endpoint state has explicit refcounts for binding, open files and scheduled work. Device-managed allocation must not free it while these survive. Teardown marks `DETACHED` and closes eligibility under the authority mutex, prevents callbacks from scheduling new work, then releases the mutex before cancelling timers/work synchronously. With the binding reference retained, close the transport and quiesce its callback producers using the selected backend's verified close/synchronization path; drain already-entered callbacks before dropping that reference. There is no assumed generic serdev callback-quiescence API. A target lacking a proven path needs a minimal reviewed kernel patch or is unsupported. Old FDs remain queryable as detached and never bind to a replacement endpoint; final reference release frees state. No teardown waits for an unreachable controller receipt. Forced unload is unsupported.

Keep serdev open with its runtime-PM usage reference while the endpoint is bound; do not permit autosuspend of the active transport. Verify the actual parent/UART driver honors that reference. Suspend preparation first inhibits/reconciles; suspend while active is refused. Unavoidable shutdown/disconnect closes local authority without claiming delivery. Resume, PM errors or changed clocks require fresh inhibited reconciliation/rearm. The controller's own expiry oscillator and output-disable behavior must remain operative through Linux/host power loss.

## Evidence and acceptance gates

Inspected Linux reference `a5ebb76233b79db01e82e061173cb73c6d2b5c6b` exports [serdev buffer-write/open/close](../../ref/linux/drivers/tty/serdev/core.c), [task/PID reference helpers](../../ref/linux/kernel/pid.c), and [task release helpers](../../ref/linux/kernel/fork.c). [Mutex documentation](https://docs.kernel.org/locking/mutex-design.html) supports using a process-context mutex, not taking it from a timer/interrupt callback. This reference is not the release kernel. Exact headers, exports, callback synchronization and PM paths must compile and pass review on the selected kernel/UART; unsupported combinations fail installation.

Required tests: every-byte-offset revoke; short/zero/error writes; delayed DMA/FIFO bytes; full RX/submission queues; simultaneous cancel/revoke/fault/teardown and stale slot clearing; expiry versus captured receipts; old-session replay after either/both peer resets; interrupted NVM boot-counter writes; sequence exhaustion; changed duplicate; cancel versus sample; lost/parsed-only/incorrect-baseline receipts; mapping/calibration invalidation; fork/dup/FD-pass/leader-exit/PID reuse/exec denial; unbind/rebind with open FDs; timer/worker stall; PM failure; recorder-loss closure. Differential firmware/model tests establish semantics; kernel race/memory tests establish implementation properties, neither proves physical behavior.

The target must supply numeric maxima for frame/queues, operation/sample horizons, clock uncertainty/drift, owner polling, write/closure/recovery delay, endpoint expiry and allowable residual physical response. All are **UNMEASURED** until retained target evidence exists. Missing values block physical qualification; they do not reopen the selected protocol/lifecycle choices above.
