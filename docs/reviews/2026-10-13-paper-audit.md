# Independent audit of the 15 research references

Historical review of the preserved pre-patch baseline. See the [remediation record](2026-10-13-review-remediation.md) for the current design changes and remaining validation gates.

Review date: 2026-10-13. This audits the proposed [system architecture](baseline/2026-10-13-volnlabs-system-architecture.md) and [source review](2026-10-13-source-review-baseline.md), rather than defending their existing choices. The custom kernel component in V1 is a fixed user requirement. The question is what it should enforce, and which research mechanisms actually fit around it.

**Coverage: all 15 references have an explicit disposition, but they have not all been fully audited or reproduced.** Eleven paper full texts were available; selected method, evaluation and limitation sections were read. The MIT essay was read; UnifoLM-WLA implementation documentation and selected source metadata were inspected; PACE and H-GenPO were identified and their primary conference abstracts read, but their full papers were inaccessible. Four projects received selected implementation-code inspection (GPT-Policy, Point4D, OxyGen, PaPE); this is not whole-repository verification. No dependencies were installed, models trained/run, benchmarks recomputed or physical experiments performed. All empirical results remain author-reported.

Architecture references below use **A:Lxxx**, meaning lines in the architecture file at review time. Findings propose corrections; this report does not modify that file. A paper's successful task execution does not establish Voln's enforcement, cancellation, timing or physical qualification.

## Findings that change the design review

1. **A bounded numeric envelope is not a general motion verifier.** A:L200–204 keeps planning/perception outside the kernel and selects fixed predicates; A:L237 rejects malformed values and incompatible frames. Both are sensible, but “admitted” must explicitly mean the named fixed predicates passed. Counterexample: two individually legal arm poses can cause an inter-arm collision. GPT-Policy's own limitation section reports such collisions. Require each supported skill to name its trusted trajectory/collision/contact checks and unsupported scenes; keep their result distinct from kernel admission. Do not imply that adopting a constrained tool controller or a custom kernel resolves this problem.

2. **The chunk contract lacks a time-indexed commitment frontier.** A:L237 has a requested horizon and A:L249 distinguishes five horizons, but A:L282 describes continuous samples only through sequence/age rules. Counterexample: a delayed replacement chunk starts at index zero although its first samples correspond to time already executed; or a smoother conditions on an unclamped old chunk while the actual dispatcher clamped it. Add prediction horizon, execution horizon, control period, absolute local target-step/time alignment, and the actual accepted prefix to the local policy-adapter contract. Superseding chunks may replace only uncommitted work; stale elapsed samples cannot replay. Revocation invalidates the entire candidate stream. This belongs in userspace/local execution with bounded kernel admission, rather than a flow sampler in the kernel. RTC is an optional implementation for compatible policies, not a reason to defer defining these semantics.

3. **Research state and authority state need separate lineage.** A:L224–231 distinguishes artifact/instance/grant but does not specify evolving model context or learned option/progress state; A:L278 requires fresh activation state. Counterexample: a restarted planner carries old “grasp complete” memory into a newly rearmed attempt; an asynchronous Corrector response marks a replacement operation successful. Record model/checkpoint/provider identity, prompt/context compiler revision, demonstration references, observation references, inference request and operation/subtask identity, and local policy state reset rules. Attach inference/progress/diagnosis outputs to the exact operation epoch. A proposal should remain bounded even when the model hot-loads weights or changes hidden state. Do not silently support unrestricted live weight updates just because a research learner does them.

4. **An observation can be fresh but geometrically unsupported.** A:L243–247 handles acquisition age and estimates, but the kernel bridge's typed-state validity policy needs an explicit support/uncertainty contract. Counterexample: a tracker supplies a current timestamp for an object hidden throughout an entire video chunk, with compounded scale drift. Keep derivation/input lineage, visibility/support interval, frame/scale calibration and the estimate's validity conditions in userspace; expose only approved typed preconditions to the fixed gate. A current inference time cannot refresh stale measurement support. Deny contact-sensitive skills when their required support is unknown.

5. **“Failure attribution” must not become an authoritative causal claim.** A:L309 lets agents append explanations and A:L313 separates evidence dimensions. Preserve this distinction in the actual event schema. Counterexample: the object drops after a kernel clamp or stale rejection, but a learned grasp/planning discriminator assigns “planner failure” and contaminates its learning data. Record the proposed, admitted and delivered action plus intervention/rejection/gap history before assigning a model diagnosis. Store classifier distribution, model version, labels and unknown/ambiguous status separately from observed fault facts. A policy's progress discrepancy is useful for detection, not independently proven task success or causal responsibility.

6. **Evaluation must measure the task and timing regime actually supported.** A:L400–406 has good fault and commercial metrics, but lacks per-skill model-performance acceptance. Counterexample: rotated views of one scene are counted as independent trials; emitted actions per second are presented as closed-loop refresh rate; near-perfect simulator success is treated as contact reliability on the fixture. Add per-workflow task-success definitions, unique episode/scene counts, interventions, reset conditions, fixed comparison budgets, camera/geometry/latency shifts and paired latency traces. Keep generated-action throughput, fresh-observation inference frequency, actual dispatch rate and physical response separate. Research metrics are references, not inherited acceptance limits.

7. **The current selective-adoption table is not evidence that every research item was assessed.** Source-review §6 explicitly calls its dispositions design decisions. Its RTC/OxyGen row is too broad to establish model compatibility, and A:L385's deferred-input language does not expose the missing full papers or implementation releases. Retain deferral where appropriate, but attach this per-item matrix and make incomplete source depth visible. No paper reviewed here proves novelty of Voln's kernel authority architecture or customer demand for it.

## License correction and release boundaries

GPT-Policy's [LICENSE at the inspected commit](https://github.com/cheng-haha/GPT-Policy/blob/2ca201638e1139fe35973c8a2d209a894b389db1/LICENSE) says: “No license has been selected for redistribution or commercial use yet.” Therefore the accurate finding is **unresolved redistribution/commercial permission**, not “open source under a noncommercial license,” nor “commercial use is prohibited by a named license.” Third-party terms remain separate. Use its paper/interface lessons; do not vendor or ship its source until rights are settled.

Public repository/checkpoint links are not a complete redistribution inventory. Weight/data dependencies, vendor controller SDKs, base models, codecs and feature-specific terms need examination for the actual shipped selection. This audit does not settle those inventories. UnifoLM's README announces Base weights/fine-tuning release on September 28; it is inaccurate to retain an older blanket “all weights pending” statement. LessMimic's inspected repository explicitly still promises a later code release. Embodied-R1.5's README acknowledges unreleased data subsets. These distinctions limit reproducibility even when a project page uses broad open-release language.

## Remaining source gaps and decision

- PACE and H-GenPO are now exactly identified; their conference abstracts are available, but full-paper revisions, methods/limitations/appendices, implementation and artifact terms remain unresolved. OpenReview access failed both through browsing and direct PDF/API requests. Do not substitute Phase-Aware Chunk Execution, Stage-Consistent PACE, or flat GenPO for them.
- UnifoLM-WLA was audited as a released project/specification, not a full-paper comparison. GTP-FA deployment code was not located/pinned. The vision-locomotion page links paper/reviews/video rather than a deployment release. LessMimic's live demo and forthcoming-code repository do not supply a reviewed complete robot stack.
- All result denominators, raw episodes, model configurations, exclusions and baselines remain unverified independently. Full papers were inspected selectively for the architecture question; this is neither a systematic literature review nor full reproduction of 15 works.

**Architectural judgment:** retain a small kernel authority/transport boundary because it is required and has a named enforcement job. Correct the surrounding policy, observation, chunk and evidence contracts before implementation. None of these sources justifies adding perception, neural inference, learned failure diagnosis or flow sampling to the kernel. Nor does it justify dismissing those mechanisms as irrelevant: they determine which data and commitment semantics the userspace boundary must preserve. Adopt no new training stack now; attach explicit later entry conditions to model-specific experiments and qualify the first workflow independently.
